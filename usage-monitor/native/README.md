# Offline upstream scanner

`codex-usage-offline --codex-home PATH --database PATH [--timezone IANA_ZONE]`

`codex-usage-offline --query-snapshot PATH [--turn-id ID] [--byte-limit N]`

The separate query-snapshot command reads one explicit JSONL file prefix without a database or history scan. It checks the file UUID against its own session metadata, requires contiguous explicit turn context, and returns only safe lineage, turn lifecycle markers, structured agent-dispatch IDs/kinds, and five numeric cumulative counters before/through the selected turn. Later turns are excluded. Missing or ambiguous scope, malformed complete records, invalid numbers and unsafe arithmetic fail with static error codes. A completed turn without an explicit valid token-usage object fails with `query_missing_token_usage`; absence of telemetry never becomes a confirmed zero. Active turns before their first usage event and explicitly recorded zero usage remain supported. Non-newline-terminated bytes are flagged as a partial tail and are not counted. Compressed query sources are explicitly unsupported because compressed byte offsets do not provide the required JSONL-prefix boundary.

The generated `scanner_query.rs` consists of the byte-identical original scanner followed by `src/query_counting.rs`. This checked adapter invokes the original private normalize/subtract/convert functions, preserving last-usage preference, reset clamping and subset behavior; it implements no alternative counting algorithm. The regular scanner and upstream library assertions remain unchanged. Query snapshots do not emit prompts, messages, tool arguments/outputs, names or arbitrary parser errors. A caller must protect source prefixes against replacement, register exact child turns against parent dispatch IDs, and verify all selected turn completions before claiming a complete request measurement. Parent-session lineage alone proves a chat family, not a specific request. The query output rejects counts above JavaScript's exact integer range.

This small harness invokes the original `scan_codex_usage` from Codex Usage Desktop 4.2.0, MIT, immutable commit `6bd0eed7b108497aa50051580387345340e3167f`. The complete selected originals are in `upstream/`; their Git blob and SHA-256 checksums are recorded in `upstream-manifest.json`. The original scanner, token-counter logic, cumulative-reset rules, model/project attribution, archive precedence, compression support, quota-counter parsing, rollup merge, and scan transaction are reused. No rollout parser was reimplemented in Python.

## Offline execution and privacy

The CLI requires one existing, explicit Codex home containing `sessions/` or `archived_sessions/`. It performs no home discovery, WSL lookup, subprocess source lookup, account requests, authentication reads, or HTTP calls. It does not depend on the desktop application or any Tauri, reqwest, HTTP, TLS, or OAuth library. Standard Rust and platform runtime libraries may contain general networking primitives; the scanner has no reachable network operation. Setup may download compilers and pinned public crates before this executable exists.

The upstream parser necessarily reads local rollout JSONL or Zstandard content into process memory. The CLI never emits message bodies, prompt titles, thread names, or parser error strings. No real user logs are used in build/test validation. Only static error codes go to stderr. Successful stdout is a compact JSON object containing `schemaVersion`, `engineVersion`, `sourceCommit`, `scanId`, `scannedAt`, `timezone`, `importedDays`, `filesScanned`, `filesParsed`, `filesReused`, and `bytesRead`.

Persistence is limited to the upstream numeric rollups and safe project/model/path metadata. `session_file_rollups.prompt_title` is bound as SQL NULL. `project_session_index.search_text` is empty; its `detail_json` contains exactly `agentSessionId`, `parentSessionId`, `agentPath`, `agentNickname`, and `agentRole`. Numeric quota timing/percentage rollups are local parsed telemetry, not fetched account limits. Message bodies and raw logs are never persisted. Existing source state and authentication files are never written.

`build.rs` applies four narrow transformations to generated files in Cargo's build directory. It replaces the pricing HTTP loader with an unconditional offline error, uses `url::Url` directly instead of reqwest's re-export of that same pure URL parser (and relocates the three original test fixture includes), binds prompt titles as NULL at the database boundary, and restricts the stored project index to the five lineage fields. All original upstream files remain byte-for-byte pinned. The source/patch manifest records exact hashes and the readable diff is in `patches/offline-only.patch`.

Prices come from upstream `PricingSource::load_cached_or_embedded(None)`, so this build always uses the pinned embedded pricing snapshot. Costs are estimates and can become stale; unknown models keep upstream unavailable/fallback behavior. No pricing download or external cache lookup occurs during scanning.

## Cache ownership and completion

Only a new database path or an existing owned database is accepted. The CLI rejects database paths inside the source home, stock desktop caches, invalid/mismatched markers, missing upstream columns, source-home mismatches, invalid timezones, and completed-cache timezone changes. The marker is a single row in `offline_engine_meta(schema_version INTEGER, source_commit TEXT, codex_home TEXT)`, with schema version 1, the exact upstream commit, and the canonical absolute home. `PRAGMA application_id` is `0x43554F46` (`CUOF`). A changed source or timezone needs a fresh database, allowing the outer refresh layer to preserve the previously completed cache until validation succeeds.

The original SQLite scan transaction includes all rollups, the project index, and `scan_runs`. Scan failure rolls back that transaction. CLI success additionally requires a newly committed `scan_runs.id` matching the returned scan metadata; nonzero totals, mtimes, sleeps, and process existence are not completion signals. The connection is checkpointed with `wal_checkpoint(TRUNCATE)`, requires a nonbusy result, and closes before success. The outer Python refresh layer uses a stage copy and validates the complete accounting ledger before publishing it.

The counters `filesParsed` and `bytesRead` preserve upstream semantics. They count token-parsed files and their stored compressed size, not every metadata read or decompressed byte. Because privacy removes cached titles, upstream metadata backfill can reread an unchanged file even when `filesParsed` is zero. That affects performance only; title contents remain confined to process memory.

## Build and tests

Build with `cargo build --release --locked --manifest-path native/Cargo.toml`. The package includes `Cargo.lock` and sources only. Installed compilers, crate downloads, build outputs, binaries, databases, and user data stay outside this directory.

Run `cargo test --locked --manifest-path native/Cargo.toml -- --test-threads=1`. The library target runs all selected original upstream assertions, including scanner/database/session/replay/project/pricing tests, with only the HTTP loader and pure URL type reference adapted for offline compilation. The production binary separately uses the privacy persistence transformations. `tests/offline_cli.rs` invokes that actual production binary to verify the five token counters, model/project totals, lineage, SQLite/WAL secret exclusion, transaction rollback, cache guards, compressed archived deduplication, and empty scans.

Run `python native/verify_sources.py` to verify all packaged source, patch, and upstream Git-blob hashes without network access. Add `--generated-dir CARGO_OUT_DIR` to verify the exact bytes produced by the four build transformations. One upstream test is ignored by default; it can also be run with a synthetic compressed fixture and a genuine `zstd` command, using `CODEX_USAGE_ZSTD_FIXTURE` and `cargo test ... -- --ignored`.
